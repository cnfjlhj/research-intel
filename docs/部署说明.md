# 部署说明

## 方案 A：宿主机部署

适合已经有稳定 Linux 机器、tmux、cron、Telegram 代理环境的人。

### 前置条件

- Node.js 20+
- `pdftotext`
  - Debian / Ubuntu: `sudo apt-get install poppler-utils`
- Chrome / Chromium
  - 用于 HTML 本地浏览器校验
- `tmux` 与 `codex`
  - 默认部署路径需要这两项

### 步骤

1. 安装依赖
   ```bash
   npm install
   cp .env.example .env
   ```
   然后至少填好这些配置：
   - 模型接口：`RESEARCH_INTEL_API_BASE_URL`、`RESEARCH_INTEL_API_KEY`、`RESEARCH_INTEL_HTML_MODELS`
   - 可选超时：`RESEARCH_INTEL_CHAT_TIMEOUT_MS`，默认 `60000`，用于限制 HTML 生成与 daily curation 的单次模型请求等待时间
   - Telegram：`TELEGRAM_BOT_TOKEN`、`TELEGRAM_CHAT_ID`
   - Web：`RESEARCH_INTEL_WEB_PASSWORD`、`RESEARCH_INTEL_WEB_SESSION_SECRET`
   - 如果访问 Telegram API 需要代理，再设置 `TELEGRAM_USE_PROXY=true` 与 `TELEGRAM_PROXY_URL`
   - `RESEARCH_INTEL_CODEX_HTML_MODEL` 默认建议保留；只有你明确想禁用 Codex HTML 强化时才留空
2. 初始化画像
   - 想快速试跑：
     ```bash
     npm run profile:example
     ```
   - 想按自己的研究方向逐步回答问题：
      ```bash
      npm run profile:init
      ```

   `profile:example` 会把示例画像写入 `work/research-intel/profile/`，更适合第一次试跑或空白环境。
3. 跑一轮日报验证链路
   ```bash
   npm run daily:no-telegram
   ```
   如果无副作用试跑通过，而且 Telegram 已配置完成，再执行：
   ```bash
   npm run daily
   ```
4. 启动 Web
   ```bash
   npm run web:start
   npm run web:status
   ```
5. 安装 cron
   ```bash
   npm run cron:install
   ```

`cron:install` 会从 `work/research-intel/profile/research_brief.md` 读取 `timezone` 和 `send_time`，再按 `RESEARCH_INTEL_VERIFY_DELAY_MINUTES` 自动生成验证任务时间。

## 方案 B：Docker Compose

适合快速试用和一键部署。

### 步骤

1. 准备环境变量
   ```bash
   cp .env.example .env
   ```
2. 启动 Web
   ```bash
   docker compose up -d web
   ```
3. 初始化画像
   - 想快速试跑：
     ```bash
     docker compose run --rm profile-example
     ```
   - 想手动交互填写：
     ```bash
     docker compose run --rm init-profile
     ```

   `profile-example` 会把示例画像写入挂载的 `work/research-intel/profile/`。
4. 手动跑一轮无副作用验证
   ```bash
   docker compose run --rm daily-no-telegram
   ```
5. 确认链路没问题后，再改用真实画像和 Telegram 推送
   ```bash
   docker compose run --rm daily
   ```
6. 启动调度循环
   ```bash
   docker compose up -d scheduler
   ```

## 关于 `RESEARCH_INTEL_RUN_MODE`

- `direct`
  - 降级与调试路径
  - 不依赖 Codex CLI
  - `RESEARCH_INTEL_CODEX_HTML_MODEL` 留空时，会跳过 Codex HTML 强化
- `codex`
  - 默认推荐值
  - 需要宿主机中可用的 `codex`、`tmux`
  - 容器默认不建议使用

## HTTPS / 外网暴露

公开访问 Web 控制台之前，请先确认：

- 已设置强密码 `RESEARCH_INTEL_WEB_PASSWORD`
- 已设置随机 `RESEARCH_INTEL_WEB_SESSION_SECRET`
- 反向代理层启用了 HTTPS
- 不把 `work/` 和 `research-intel-records/` 整目录直接挂到公网静态目录
