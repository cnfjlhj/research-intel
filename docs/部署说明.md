# 部署说明

## 方案 A：宿主机部署

适合已经有稳定 Linux 机器、tmux、cron、Telegram 代理环境的人。

### 前置条件

- Node.js 20+
- `pdftotext`
  - Debian / Ubuntu: `sudo apt-get install poppler-utils`
- Chrome / Chromium
  - 用于 HTML 本地浏览器校验
- `tmux` 与 `codex`
  - 默认部署路径需要这两项
  - 开始前先确保当前 shell 里 `codex exec -m gpt-5.4 ...` 已经能独立跑通

### 步骤

1. 安装依赖
   ```bash
   npm install
   cp .env.example .env
   ```
   Research Intel 的公开默认路径是直接调用 `codex exec -m gpt-5.4` 生成论文 HTML。仓库本身不负责你的 Codex 登录或 provider 配置；这些要先在 Codex CLI 自己的配置层完成。

   第一次本地试跑时，不要把所有变量都一起填。建议先按这个顺序：
   - 先确认当前 shell 里 `codex exec ...` 已经独立可用
   - `.env` 里先至少改掉 Web 登录的两项：
     - `RESEARCH_INTEL_WEB_PASSWORD`
     - `RESEARCH_INTEL_WEB_SESSION_SECRET`
   - 第一次先跑 `npm run daily:no-telegram`，所以 `TELEGRAM_BOT_TOKEN`、`TELEGRAM_CHAT_ID` 可以先留空
   - `RESEARCH_INTEL_CODEX_HTML_MODEL`、`RESEARCH_INTEL_CODEX_HTML_REASONING_EFFORT`、`RESEARCH_INTEL_CODEX_HTML_TIMEOUT_MS` 一般先保留 `.env.example` 默认值
   - `RESEARCH_INTEL_CHROME_PATH` 只有在浏览器校验阶段提示找不到浏览器时才需要手动设置

   最小可运行配置通常从这两项开始：

   ```dotenv
   RESEARCH_INTEL_WEB_PASSWORD=replace-with-a-strong-password
   RESEARCH_INTEL_WEB_SESSION_SECRET=replace-with-a-long-random-secret
   ```
2. 初始化画像
   - 第一次想快速试跑：
     ```bash
     npm run profile:example
     ```
   - 想按自己的研究方向逐步回答问题：
      ```bash
      npm run profile:init
      ```
   - 想直接走 Web 首次填写：
      ```bash
      npm run web:start
      ```
      然后打开 `http://127.0.0.1:3086/research-intel/`，登录后进入 `编辑区`：
      - 先填 `首次使用 / 研究画像向导`
      - 如有现成论文清单，再用 `论文导入 / 批量种子录入`
      - 可直接勾选“保存后立即触发一次今日运行”

   `profile:example` 会把示例画像写入 `work/research-intel/profile/`，更适合第一次试跑或空白环境。
3. 跑一轮日报验证链路
   ```bash
   npm run daily:no-telegram
   ```
   第一次一定先跑这条无推送路径。先确认本地链路已经稳定，再去接 Telegram。

   这一步现在不只是看有没有 `brief.md` 和单篇 `index.html`，还要确认 route/dependency 语义工件已经落盘：
   - `work/research-intel/daily/<date>/reading_route.json`
   - `work/research-intel/daily/<date>/dependency_graph.json`
   - `work/research-intel/daily/<date>/dependency_cards/`
   - `work/research-intel/daily/<date>/session_contexts/`
   - `research-intel-records/daily/<date>/reading_route.json`
   - `research-intel-records/daily/<date>/dependency_graph.json`

   如果无副作用试跑通过，而且 Telegram 已配置完成，再执行：
   ```bash
   npm run daily
   ```
4. 启动 Web
   ```bash
   npm run web:start
   npm run web:status
   ```
   打开 `http://127.0.0.1:3086/research-intel/` 后，你应该至少能看到：
   - 最近一次运行状态
   - 历史日报列表
   - 当天论文卡片和单篇 HTML 入口
   - `编辑区` 里的研究画像、种子论文和反馈入口
5. 安装 cron
   ```bash
   npm run cron:install
   ```

`cron:install` 会从 `work/research-intel/profile/research_brief.md` 读取 `timezone` 和 `send_time`，再按 `RESEARCH_INTEL_VERIFY_DELAY_MINUTES` 自动生成验证任务时间。

### 现有宿主机升级

如果你的宿主机目录已经在跑 Web/cron，不要把它当成开发仓库原地改到失控。更稳的做法是：

1. 在本地 Git 仓库完成改动并跑测试。
2. 把代码同步到宿主机部署目录，但保留宿主机自己的 `.env`、`work/`、`research-intel-records/`。
3. 同步后先做健康检查，再决定是否补跑当天任务。

推荐同步命令：

```bash
rsync -az --exclude '.git/' \
  --exclude 'node_modules/' \
  --exclude 'work/' \
  --exclude 'research-intel-records/' \
  --exclude '.env' \
  /path/to/local/research-intel/ host:/path/to/deploy/research-intel/
```

推荐验收命令：

```bash
ssh host 'bash -lc "cd /path/to/deploy/research-intel && node --test tests/codex-enhancement-config.test.js tests/test-research-intel-codex-html.js"'
ssh host 'bash -lc "cd /path/to/deploy/research-intel && bash scripts/research-intel/status-web.sh"'
```

如果宿主机上的 `npm`、`node`、`codex` 依赖 `nvm` 或登录 shell 初始化，远端命令尽量统一包在 `bash -lc` 里执行。

## 方案 B：Docker Compose

适合快速试用，或者在宿主机已经配置好 Codex CLI 的前提下做容器化部署。

### 步骤

1. 准备环境变量
   ```bash
   cp .env.example .env
   ```
   Compose 镜像会安装 `codex` CLI，并默认把宿主机 `${HOME}/.codex` 挂载到容器内的 `/root/.codex`。
   如果你的环境拿不到这个目录，优先改用宿主机部署，不要假设容器会自动完成 Codex 登录。
2. 启动 Web
   ```bash
   docker compose up -d web
   ```
3. 初始化画像
   - 想快速试跑：
     ```bash
     docker compose run --rm profile-example
     ```
   - 想手动交互填写：
     ```bash
     docker compose run --rm init-profile
     ```

   `profile-example` 会把示例画像写入挂载的 `work/research-intel/profile/`。
4. 手动跑一轮无副作用验证
   ```bash
   docker compose run --rm daily-no-telegram
   ```
5. 确认链路没问题后，再改用真实画像和 Telegram 推送
   ```bash
   docker compose run --rm daily
   ```
6. 启动调度循环
   ```bash
   docker compose up -d scheduler
   ```

## 验收重点

部署验证时，至少确认下面四件事：

1. `reading_route.json` 已经先于单篇 HTML 作为 route planning 结果落盘。
2. 每篇主推论文目录里仍然有 `paper.pdf`、`index.html`、`paper_card.json`、浏览器校验结果。
3. `dependency_cards/` 与 `session_contexts/` 同时存在于 `work/` 和 `research-intel-records/`。
4. Web 日报页能直接看到 `Raw Reading Route` 与 `dependency_graph.json` 链接。

## HTTPS / 外网暴露

公开访问 Web 控制台之前，请先确认：

- 已设置强密码 `RESEARCH_INTEL_WEB_PASSWORD`
- 已设置随机 `RESEARCH_INTEL_WEB_SESSION_SECRET`
- 反向代理层启用了 HTTPS
- 不把 `work/` 和 `research-intel-records/` 整目录直接挂到公网静态目录
