# 架构说明

`Research Intel` 的主链路可以概括成六层：

1. 研究画像层
   - `research_brief.md`
   - `seed_papers.jsonl`
   - `feedback.jsonl`
   - `method_taxonomy.json`
   - `method_tree_notes.md`

2. 发现与筛选层
   - arXiv 检索
   - OpenReview 与外部 blog / code enrichment
   - 去重、相关性打分、`must_read / watchlist` 双池选择

3. 阅读路线与局部依赖层
   - 先生成 `reading_route.json` / `reading_route.md`
   - 在真正进入单篇生成前固定 route order、`routeRole`、`compareAxes`
   - 只允许 backward-only 局部依赖边，写入 `dependency_graph.json`
   - 每完成一篇，沉淀 `dependency_cards/*.json` 与 `session_contexts/*.json`

4. 单篇档案层
   - 下载 PDF
   - 抽取文本
   - 调用模型生成 HTML 档案
   - 本地浏览器校验并修复

5. 长期账本层
   - `method_tree.md`
   - `method_tree.json`
   - 每日 `method_tree_delta.md`

6. 交付层
   - Telegram 文档推送
   - Web 控制台
   - 发送历史与验证回补

## 运行模式

### direct

`daily-run.js` 直接完成当日链路。

适合：

- 开源部署
- 容器化部署
- 普通自托管场景

### codex

`codex-supervisor.js -> tmux worker -> heartbeat-monitor.js`

适合：

- 你已经有成熟的 Codex/Codex CLI 环境
- 希望保留可 attach 的 worker 会话
- 希望把“脚本链路 + Codex 自主修复”绑在一起

## 目录语义

- `examples/profile/default/`
  - 脱敏示例画像
- `work/research-intel/profile/`
  - 当前实例实际使用的画像
- `work/research-intel/runtime/`
  - 会话、心跳、PID、提示词、监控状态
- `work/research-intel/daily/`
  - 当日中间产物与工作目录
  - 其中 `reading_route.*` / `dependency_graph.json` / `dependency_cards/` / `session_contexts/` 是语义层工件
- `research-intel-records/`
  - 对外展示和长期保留的日报、账本、历史
  - 与 `work/` 双写语义工件，但不默认复制所有重资产

## 关键约束

- `paper.pdf` 仍然是单篇 HTML 的第一真相源，前序依赖卡只能做受控补充上下文
- `reading_route.json` 现在是机器主输入，`reading_order.md` 退回为人类展示层
- route planning 必须前置，不能等所有单篇 HTML 都生成完再反推阅读顺序
- `dependency_cards/*.json` 只存压缩后的公共语义，不存冗长推理过程

## 设计取向

- 优先精度，而不是为了凑篇数放松门槛
- 优先“今天为什么看”，而不是模板化摘要
- 优先长期方法积累，而不是只给一次性通知
- 优先用户可控的文件与目录，而不是埋进不可见数据库
