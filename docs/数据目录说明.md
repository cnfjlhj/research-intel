# 数据目录说明

## 代码目录

- `scripts/research-intel/`
- `scripts/bootstrap/`
- `tests/`
- `examples/`

这些目录可以进 Git。

## 运行目录

### `work/research-intel/profile/`

真实研究画像：

- `research_brief.md`
- `seed_papers.jsonl`
- `feedback.jsonl`
- `method_taxonomy.json`
- `method_tree_notes.md`
- `runtime.env`（可选，不建议进 Git）

### `work/research-intel/runtime/`

瞬时运行状态：

- `current-run.json`
- `heartbeat.json`
- `latest-session.json`
- `worker-progress.md`
- `research-intel-web.pid`

### `work/research-intel/daily/<date>/`

中间产物与工作目录：

- `reading_route.json`
  - 机器主读版本的阅读路线，定义稳定顺序、`routeRole`、`compareAxes`
- `reading_route.md`
  - 人类可读版本，供 Web 与人工审阅
- `dependency_graph.json`
  - backward-only 局部依赖图
- `dependency_cards/`
  - 每篇论文生成后的结构化依赖卡，供后续论文复用
- `session_contexts/`
  - 每篇论文启动前真实装配的上下文包
- `papers/`
  - 单篇论文工作目录，包含 `paper.pdf`、提取文本、HTML、校验结果、`paper_card.json`
- `brief.md`
- `reading_order.md`
  - 人类阅读视图，不再作为机器主输入
- `daily_curation.json`
- `telegram_message.txt`

## 发布目录

### `research-intel-records/daily/<date>/`

对外展示的当日日报：

- `brief.md`
- `reading_order.md`
- `reading_route.md`
- `reading_route.json`
- `dependency_graph.json`
- `dependency_cards/`
- `session_contexts/`
- `selected_papers.json`
- `watchlist_papers.json`
- `method_tree.md`
- `manifest.json`

其中需要特别区分：

- `reading_route.json`
  - 机器主真相，描述前置 route planning 的结果
- `reading_order.md`
  - 展示性摘要，帮助人类快速浏览
- `dependency_cards/*.json` 与 `session_contexts/*.json`
  - 都会双写到 `work/` 与 `research-intel-records/`
  - 目的是保留可审计的语义轨迹，而不是只把真正用过的上下文留在工作区

### `research-intel-records/knowledge/`

长期账本：

- `method_tree.md`
- `method_tree.json`

### `research-intel-records/history/`

历史状态：

- `runs.jsonl`
- `sent_papers.jsonl`
- `telegram_receipts.jsonl`

## 为什么这些目录要分开

- `work/` 方便失败恢复和中间调试
- `research-intel-records/` 方便持久展示和历史回放
- 分开之后，公开仓、备份策略、Web 展示权限都更清楚
- 语义工件双写后，可以单独回放某一天的 route / dependency 决策，而不用重新进入原始 tmux 会话
